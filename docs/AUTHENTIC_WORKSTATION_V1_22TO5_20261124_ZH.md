# `authentic_workstation_v1`：真实开源软件套件零乘数修订与 2h 无步数上限双模型实测报告（2026-11-25）

## 一、核心结论与运行契约升级总览

围绕新版 `$paragui-case-design` 规范及后续两轮审阅要求，[`experiments/authentic_workstation_v1.py`](../experiments/authentic_workstation_v1.py) 与 [`tasks/authentic_workstation_v1/`](../tasks/authentic_workstation_v1/) 完成了从底层容器沙盒、评分契约到运行边界的全部定稿：

1. **零步数上限 + `2 小时 (7200s)` 超长墙钟窗口**：彻底移除了全部 22 个任务 `TASK_META`、系统提示词与 `AwRoleMcpBridge` 中的 `max_cua_calls` 拦截及 `time budget` 提示文本，并将 `iso_role_timeout_s` 与 `conc_role_timeout_s` 统一放宽至 **`7200s`（2 小时）**。实测 **40 个容器角色实例 `40/40` 全部由模型自主正常退出（`status = "done"`，零超时、零步数截断）**，单角色自然 GUI 调用最高达 **`178` 次**（单局双角色合计 **`307` 次**），单局自然运行耗时最高达 **`3893.4s`（`64.9 分钟`，其中双角色并发重叠 `2414.5s = 40.2 分钟`）**。
2. **零 `j_mult` 乘数放大的纯子项对称评分**：在 [`common.py`](../tasks/authentic_workstation_v1/common.py) 中彻底移除了 `j_mult = 0.75`，`score_a`、`score_b`、`mean_score` 在单人 `isolated` 与双人 `shared` 模式下保持 100% 相同的子项权重与分母；`checks_joint` 仅检验跨角色契约与共享制品完整性并门控 `joint_pass`。
3. **`Xvfb -auth` + `UID 2000` 密封沙盒 + `mount_studio_ro: True` 自然只读自检**：封堵抽象 X11 套接字与 `/proc/<pid>/root` 写穿透，同时将 `/srv/studio_project` 以 `:ro` 只读挂载进 `guest_bash`，使智能体可在 GUI 保存后用 `lrelease`、`openpyxl`、`zipfile`、`PIL` 真实自检，而一切修改仍必须通过桌面真实 GUI 窗口完成。
4. **真实规模数据与零剧透工单**：`AW-14`（`72` 行酶标/电泳）、`AW-15`（`48` 行临床透析）、`AW-19`（`56` 行采购/租约明细 + `10` 处合同红线）全部移除题面内联公式并修复 `"2.875"` / `"2.75"` 容差，`AW-12` 拆分为双子路由 SPA 模块。静态审计 `24/24 PASS | 0 FAIL | 0 WARN`，五门禁 `22/22` 全通过。

1. **即使彻底放开至 `2h` 且完全取消 GUI 步数上限，两款前沿模型的并发 `joint_pass` 仍同步由 `100% (5/5)` 跌至 `80% (4/5)`**，`gpt-6.1-sol` 连续均分真实下跌 **`-6.79%`**（`AW-15` 跌 `-22.83%`、`AW-19` 跌 `-11.11%`），`gpt-6-astra` 在 `AW-12` 真实下跌 **`-6.93%`** 且在 `AW-19` 苦战 **`64.9 分钟`、`307` 次 GUI 调用、`13.39M` Token** 后仍因并发保存覆盖导致 `joint_pass` 失败（`True -> False`）。
2. **放开时间与步数边界后，`mount_studio_ro: True` 揭示了“只读 CLI 自检将部分准确率损失转化为 2–3.6 倍长程自愈开销”的清晰分界**：`gpt-6-astra` 在 `AW-14`（`25.3m`）、`AW-15`（承受 `46` 次误按键后耗费 `28.9m` 与 `240` 次 GUI 调用反复跑 `lrelease` 返工修复）与 `AW-20`（`42.8m`、`260` 次 GUI 调用、`9.80M` Token）中越过了原 `25m / 140 步` 边界才完成自愈，使 `shared` 单局平均墙钟耗时从 `16.4 分钟` 飙升至 **`36.2 分钟`（`2.17x`）**、平均输入 Token 膨胀 **`2.33x`**、总误按键升至 **`66` 次**。
