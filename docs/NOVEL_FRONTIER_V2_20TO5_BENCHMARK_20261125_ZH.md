## 二、实机容器探测与 20 候选筛选过程中的真实发现与踩坑记录

1. **`Qt5 Assistant` 对称过滤器“搭便车”与互斥过滤器反转实验（`NF2-05`）**：
   - 首轮（Wave 1）将两个角色的目标手册同置于 `REV_C_CERTIFIED` 过滤器下：单人模式 Role A 未能切出过滤器得 `0.00`（总均分 `0.500`），而并发模式下 Role B 切出 `REV_C_CERTIFIED` 反而帮同伴直接看到了页面，出现 `0.500 -> 1.000`（`+0.500`）的合作正外部性。
   - 二轮将其改为互斥子系统过滤器（`BUS_ICD_ARINC429_ONLY` vs `FCS_BODE_MIL9490D_ONLY`，激活其一即隐藏对方手册）：`gpt-6.1-sol` 立即反转出 **`0.8400 -> 0.6100`（`Δ = -0.2300`）** 的真实竞争掉分；而 `gpt-6-astra` 在并发下耗费 **`2.76x` GUI 步数（`78 -> 215`）** 与 **`3.47x` Token（`2.52M -> 8.74M`）**，同时因同伴打开了隐藏的 `Filter Toolbar` 产生跨角色可见性外溢。此外捕获了 `qwen_cua_driver` 通过 `open_app("/usr/lib/qt5/bin/assistant")` 裸启动新实例丢失 `-collectionFile` 的现象，通过二进制包装器根治。
2. **私有工作区下紧耦合偏好的数学黄金不等式（`preferred_A + floor_B <= CAP < preferred_A + preferred_B`）**：
   - 首轮在拆分私有 `/workspace` 后，`NF2-14, 16, 18, 19` 的单边推荐值满足 `preferred_A + floor_B > CAP`：单人模式下因看不到缺席同伴的 `floor_B` 而选 `preferred_A` 误触联合上限扣分（`0.887–0.905`），并发模式下双方却通过共享表协调拿满分（`NF2-18/19` 出现 `0.902 -> 1.000` 倒挂）。确立 `preferred_i = floor_i + 0.75 * (CAP - floor_A - floor_B)` 不等式后，单人独立选推荐值 100% 合法，仅当双人并发盲选推荐值时触发 `CAP + 0.50 * Δ > CAP` 超限冲突。
3. **纯单页 Web 原语（`NF2-02/03/04/08`）与重型原生桌面软件的时长分野**：
   - 实测发现即便配 400 行 SQLite 账本，`ServiceWorker`（`NF2-02`）、`IndexedDB`（`NF2-03`）、`SharedWorker`（`NF2-04`）与剪贴板金库（`NF2-08`）因 Web DOM 仅需 10–35 步点击，`87s–171s` 即告结束；相比之下，`Blender VSE`（`NF2-11`, `735s–1082s`）、`FreeCAD`（`NF2-12`, `694s–1006s`）、`QGIS`（`NF2-13`, `628s–1082s`）与单例 `GIMP`（`NF2-06/18`, `652s–994s`）天然维持 8–18 分钟的高密度并发重叠窗口。
4. **真实软件工程细节捕获**：
   - `FreeCAD 0.20` 的 StartWorkbench 内嵌 `QtWebEngine`，容器内需设置 `QTWEBENGINE_DISABLE_SANDBOX=1`；无头构建 `.qgs` 工程时 `QgsApplication` 需 `QT_QPA_PLATFORM=offscreen`；`Graphviz dot -Tsvg` 会将连字符 `-` 转义为 XML 实体 `&#45;`（判分需先 `html.unescape`）；跨容器挂载裸 Git 仓库需配置 `safe.directory = '*'`。
