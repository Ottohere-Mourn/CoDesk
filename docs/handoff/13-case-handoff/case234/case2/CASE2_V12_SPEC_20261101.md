## v1.2 symmetric workflow change

1. B's home page keeps the source ticket, order lines, delivery evidence and policy visible, and adds a compact independent pre-verification form. Before reading a handoff message or opening a Case Review, B records eligibility, affected line, evidence, shipping treatment and independently proposed total. It is a genuine double-check record and is scored by the Oracle; it does not pre-fill or reveal A's answer.
2. A saves the existing structured Case Review. The saved-review page exposes the actual generated Review ID. A must send that ID to B in a collaboration message and must not put the proposed refund amount in the message.
3. B's home page never polls for, auto-opens or displays the latest Review ID. After saving the pre-verification and reading A's message, B enters that ID into the ordinary Review lookup on B's GUI. B compares that opened review with the saved pre-verification and source records, then issues the matching refund and resolves the ticket.
4. The server records versioned B pre-verification rows and their digest, denies B's Review GUI route before the pre-verification exists, and records successful B GUI Review opens with the pre-verification ID. The refund must continue to cite A's latest valid Review. Oracle and handoff audit jointly record and check: A saves Review; B saves pre-verification; A sends the actual Review ID; B actually reads that message; B opens that same Review in its GUI; B issues the linked refund; B resolves the ticket.
5. If a shared window lets B see the Review ID before reading the message, preserve the trace; the strict handoff audit must fail. A successful business result, strict collaboration order, execution validity and reset/cleanup remain separate results.
