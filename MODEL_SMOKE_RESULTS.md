- Conditions: Solo, Naive Shared, Recovery-aware; three complete episodes per task/condition (18 total). An earlier preflight attempt that stopped before any Qwen action/evaluation is preserved separately and excluded from these results. Failures are retained as observed; no repeat was overwritten.
- After each episode, `guest.reset_clean` passed in the event log and a new clean desktop was captured. Provenance exists for 18/18 episodes, with 18 unique run IDs and matching OSWorld/task versions. All run-created containers are destroyed; no project-labeled containers remain active.

GUI+Human shared evaluation checks both document goals and cross-window contamination.

## Metric definitions

- **Success/failure:** the fixed programmatic evaluator result. Shared success requires both actors’ expected final state.
- **Focus conflicts:** number of contiguous Qwen input episodes sent while a known active window differs from the task target; consecutive low-level typing/key actions in the same wrong window count once. Unknown focus is not counted as a known conflict.
- **Invalid actions:** actor GUI/CLI actions whose event outcome was not `ok`.
- **Recovery steps:** Qwen model decisions after the first other-actor action in a shared episode; zero for Solo.
- **Total action steps:** recorded Guest GUI/CLI action events by actors and scheduler, excluding task setup/environment initialization. Qwen decision count is shown separately.

## Failure analysis

- **Model capability / grounding:** GUI Focus Solo repeat 03 failed because Qwen’s initial target click did not activate the Document; the required text was not in Document. The other two Focus Solo repeats passed. GUI+CLI Solo passed 3/3, so the shared failures below are not explained by a general inability to edit the form.
- **Interaction conflict — focus routing:** all three Naive Shared focus episodes failed after HumanReplay focused Chat. Qwen typed `Approved` into Chat, leaving Document empty and contaminating the HumanReplay window. Both scripted HumanReplay actions and Qwen actions returned valid action outcomes; this is an interaction failure, not an invalid-action failure. Focus-aware scheduling returned focus to Document and passed 3/3.
- **Interaction conflict — stale shared state:** all three GUI+CLI Naive episodes ended with `gui_status=Approved` but `cli_note=Draft`. CLI’s update was performed successfully, but Qwen later saved its stale form snapshot and overwrote that update. This repeated in 3/3 runs; no invalid GUI/CLI action was recorded.
- **Model capability after recovery:** GUI+CLI Recovery-aware preserved `cli_note=Reviewed by CLI` in all 3 runs, showing that the public Refresh step and scheduler ran. Two runs failed because Qwen left the GUI field as `DrafApproved`; one run edited it to `Approved` and passed. The two failures are text-selection/editing errors after a successful refresh, not scheduler failures.
- **Scheduler issue:** none observed. Focus reacquisition succeeded on each focus-aware turn; browser recovery recorded its one scheduled Refresh action each episode. Invalid actor actions: 0/18 episodes.

The trajectories and observation screenshots are linked per episode above. The saved `events.jsonl` contains actor, action, active-window/revision and reset events; `model_trace.jsonl` contains each Qwen response, parsed action, screenshot digest, and model timing. Provenance and resource lifecycle records are in each episode directory as `provenance.json` and `resource-events.jsonl`.

## Reproduction

From the project root, with the existing OSWorld V2.1 checkout and local model available:

```bash
python scripts/run_phase4_model_smoke.py \
  --artifact-root /mnt/raid1/mjh/Shared-Workspace-Benchmark-V0-artifacts/osworld-v2.1/phase4-model-smoke \
  --start-task focus
```

The runner preserves incomplete directories and skips complete episodes. To run only the GUI+CLI block in a fresh artifact root, use `--start-task gui-cli`.

## Limits

This is a narrow smoke test on two fixed task instances and one local model. It shows that the scripted focus-routing failure transferred to Qwen under naive sharing, and that refresh/focus scheduling changed the observed failure mode. It does not establish benchmark-wide success rates or generalize to other GUI tasks, models, or schedulers.
