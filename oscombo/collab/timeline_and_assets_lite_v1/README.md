# Case 4 Lite: native GreenLoop timeline repair

`CDD-TLA-LITE-001` reduces the original 240-call Kdenlive assembly task to a short timeline repair with a 15 desktop-call budget per actor. A reviews synthetic footage, sends B the correct middle-shot choice, and saves a three-line source manifest in the GUI editor. B replaces the 3–7 second outtake in Kdenlive and saves the intended 10-second cut while A updates that manifest. Both desktop conditions use the same assets, native project, instructions, model, collaboration channel, and Oracle; only desktop topology changes.

The original `timeline_and_assets` writer produces MLT XML that passes its offline parser but opens with an empty Project Bin and timeline in Kdenlive 21.12.3. This Lite fixture was instead created through Kdenlive's GUI: import all five media files, add three V1 clips and the A1 bed, save a native project, and normalize the three clip durations to 3/4/3 seconds. The correctly trimmed WASH clip was also staged on V2 at 11–15 seconds to keep the repair within 15 desktop calls. A fresh KVM Guest opened the native project with all five bin assets and occupied tracks visible. The private `gui_gold.kdenlive` is the result of the manual GUI repair and save, used only for regression tests.

Fixed state: 320×180 at 25 fps; V1 has `clip_01.mp4` at frames 0–74, `clip_04.mp4` at 75–174 (wrong), and `clip_03.mp4` at 175–249. A1 has `music_bed.wav` at frames 0–249. V2 stages `clip_02.mp4` at frames 275–374. Success deletes the wrong V1 middle shot, moves the staged clip to frames 75–174, and leaves V2 empty; all other shots, tracks, media bytes, and bin assets remain intact. There is no render or subtitle deliverable in this Lite variant.

The Oracle parses Kdenlive's native `main_bin`, producer resources, playlists, profile, and frame-aligned ranges. It also verifies the saved manifest, every source-media hash, and A's source-selection message. The initial project fails; the real GUI-saved repair plus corrected manifest passes. It rejects wrong tracks and modified media. It does not treat a visible window title alone as proof of a loaded project.

Run with the installed Case 4 KVM image and `infra/run_case4_lite_pair_pilot.py`. The two comparison commands differ only in `--condition` and fresh run/overlay roots. `--desktop-lock` serializes each shared-desktop tool action and screenshot for the harness optimization check. Run artifacts include initial/final screenshots, native project hashes, per-actor traces, collaboration events, Oracle checks, and ownership/cleanup evidence. Keep the private provider key outside run output.

The final real-agent comparison and the earlier calibration runs are recorded in `audits/case4_lite_20261030.md`. The final independent run passed, while ordinary shared and two action-locked shared runs failed.
