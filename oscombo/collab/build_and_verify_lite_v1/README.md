# Build-and-Verify Lite v1

Independent, versioned Case 3 reduction. See [TASK_CARD_ZH.md](TASK_CARD_ZH.md) for the frozen public task. The original `build_and_verify` package remains unchanged.

Real-Guest pilot outcomes and limitations are recorded in [PILOT_EVIDENCE.md](PILOT_EVIDENCE.md).
The v1.4.3/v1.4.4 follow-up, including editor-window stabilization, evaluator error handling, and new paired results, is recorded in [the follow-up audit](../../../audits/case3_followup_20261030.md). Earlier shared-desktop passes remain valid counterexamples to any claim of guaranteed shared failure.

`python -m oscombo.collab.build_and_verify_lite_v1 prepare RUN_ROOT --run-id RUN_ID` creates the run-scoped fixture, credentials and private Oracle manifest. `configure`, `serve`, `collab-serve`, `evaluate` and `reset` use the same CLI verbs as the original case.

The candidate edit is limited to `workspace/filtering.py`. The web UI and fixture are protected. Offline tests verify the Oracle and HTTP path, but a model result requires real GUI actions and screenshots.

Version 1.3.0 reduced the scripted paired path to roughly 10–15 combined GUI calls. The browser starts with Dana and Processing prepared but unsubmitted, so B reproduces the defect with Enter and reports the visible wrong rows. While A repairs the source, B stages NW-2402 without submitting it. After A saves and sends the handoff, B submits the staged case by Apply under the final source hash. The Oracle requires the live baseline Enter event and final Apply event in addition to code acceptance. The same prepared browser state and task apply to both topologies. Each role has a 12-call pilot allowance, fixed across paired conditions; actual exploratory calls are reported separately from the scripted path. The 12-call allowance is a budget calibration after the v1.3.0 lock-enabled shared pilot passed at 11/13 calls; task semantics and fixture remain the same. Version 1.4.1 clarifies that A/B handoff uses the project collaboration read_messages tool; a v1.4.0 shared pilot became invalid when B used the unrelated native wait_agent tool. Version 1.4.2 resumes B when it ends before completing the final browser test despite an A saved-revision message; this recovery is identical in both desktop topologies. An Oracle pass alone does not prove a shared-desktop focus conflict; inspect `collaboration/events.jsonl`, `web_events.jsonl`, and each actor's `actions.jsonl` for that claim.

The real-Guest pilot is `python -m infra.run_case3_lite_pair_pilot --condition CONDITION --run-root ABSOLUTE_RUN_ROOT --overlay-root ABSOLUTE_OVERLAY_ROOT --provider OSWORLD_PROVIDER_DIR --image BASE_QCOW2 --runtime QEMU_RUNTIME_IMAGE`. Set `CONDITION` to `collaborative_isolated` or `collaborative_shared`. Use distinct run and overlay roots for every attempt. `--setup-only` verifies the Guest desktops, editor, role-scoped browser sessions, and service before model execution. `--actor-timeout` defaults to 1800 seconds and must be held equal across paired conditions; a timeout is reported as `MODEL_INVALID`, not a business failure. Optional `--desktop-lock` serializes each desktop action and its screenshot per Guest; the shared condition uses one lock and isolated uses one lock per separate Guest. The pilot retains run evidence and uses `reset_owned_run` after evaluation. It requires the configured Codex CLI, MCP Python, and private provider key file on the evaluation host; see the script constants for this host's paths.
