## Root cause and workaround

**Root cause:** undetermined for the historical dual-GPU `generate()` stall. The available log proves only that generation started and missed a 600 s deadline.

**Demonstrated workaround:** on a confirmed idle single A6000, use BF16, no quantization, `device_map=auto`, a 40 GiB GPU cap plus 80 GiB CPU cap, eager attention, greedy decoding, batch 1, and a bounded 128-token diagnostic. This completed one real request and produced a parser-valid action, but took 268 s for generation with CPU offload. Treat it as a diagnostic fallback, not a proven stable full-task serving configuration.

The worker changes in `scripts/local_qwen_worker.py` expose the memory and attention options additively; omitting them preserves prior defaults. There is no evidence yet that changing attention alone fixed the dual-GPU issue, and no safe two-GPU A/B test was possible this run.
